4 problemas típicos de la maqueta real

1. El pin 1 es especial
Es el TX de la placa, el mismo que usa el cable USB. Con un LED ahí puede fallar la carga del código y no podés usar Serial. Solución: usar el pin 9.
2. El servo reinicia la placa
Si al mover la puerta la placa se reinicia o el servo tiembla, falta corriente. Solución: un capacitor de 100 a 470 µF entre 5V y GND, o alimentar el servo con una fuente aparte (con GND en común con la placa).
3. El pulsador cuenta doble
En la placa real, un toque puede leerse como dos (rebote). Solución: el antirrebote, que es el Reto 1 del código.
4. El sensor de luz no anda como en el simulador
El valor 300 depende de la luz del aula, y algunos módulos dan el valor al revés. Solución: medirlo con Serial y ajustar el umbral.

SOFTWAREArreglos y retos del código

3 arreglos obligatorios

  1. Agregar arriba de todo: #include <Servo.h>
  2. Cambiar el nombre de la variable baño por bano (el compilador puede fallar con la ñ).
  3. Cambiar el pin del baño: int bano = 9;

Reto 1: antirrebote

Idea: no aceptar un cambio del botón si pasaron menos de 30 milisegundos desde el anterior cambio. Necesitás una variable nueva que guarde cuándo fue el último cambio.

unsigned long ultimoCambio = 0;   // variable global nueva

// adentro de loop(), al leer el botón:
if (estadoBoton != estadoAnteriorBoton && millis() - ultimoCambio > 30) {
  ultimoCambio = millis();
  // acá va lo que ya hacías cuando cambia el botón
}
Pensalo: hay dos botones. ¿Alcanza con una sola variable ultimoCambio o necesitás una para cada botón?

Reto 2: monitor serie

  • En setup() agregá Serial.begin(9600);
  • Cuando cambie la escena, mostrá cuál es con Serial.println(opcion);
  • Para calibrar el sensor, mostrá Serial.println(luz); y mirá cuánto vale con luz y tapándolo. El umbral va en el medio.

Reto 3 (extra): menos código repetido

Hoy cada escena tiene sus propios digitalWrite. ¿Se puede guardar los pines en un arreglo int luces[] = {bano, living1, living2, pieza}; y usar un for para apagarlos? Si lo lográs, apagarLuces() queda de dos líneas.

Preguntas que les pueden hacer

Ensayen las respuestas. Tocá cada pregunta para ver una pista.

¿Por qué los pulsadores usan INPUT_PULLUP?

Activa una resistencia interna del Arduino. Así el pin lee HIGH cuando el botón está suelto y LOW cuando se aprieta, y el botón solo necesita conectarse a GND, sin resistencia externa.

¿Para qué sirve la resistencia de 220 Ω en cada LED?

Limita la corriente que pasa por el LED para que no se queme.

¿Qué es millis() y por qué no usaron delay()?

millis() cuenta los milisegundos desde que arrancó la placa. Sirve para medir tiempo sin frenar el programa, como hace delay(). Así el sistema sigue leyendo botones y sensor mientras espera para apagar las luces.

¿Cómo sabe el sistema que está oscuro?

Lee el sensor con analogRead, que da un valor entre 0 y 1023. Si el valor es menor al umbral (300), considera que hay poca luz y prende la luz exterior.

¿Qué cambiarían si tuvieran una semana más?

Ideas: una alarma con buzzer si la puerta queda abierta, un sensor de temperatura con ventilador, una pantalla LCD que muestre la escena activa o control desde el celular.
